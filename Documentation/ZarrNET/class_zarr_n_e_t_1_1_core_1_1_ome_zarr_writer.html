Detailed Description

Creates a new OME-Zarr v3 dataset on disk and writes pixel data into it.

Performance notes

• ZarrArray handles are opened once per level at construction time and cached for the lifetime of the writer. Re-opening on every tile (the previous behaviour) paid the cost of reading and parsing zarr.json for every single write call.

• WriteRegionAsync is guarded by a SemaphoreSlim whose width is MaxConcurrentWrites (default: logical CPU count, capped at 16). Callers can fire many writes concurrently and the semaphore prevents the store from being overwhelmed while still keeping all cores busy.

• Metadata for all levels is written in parallel during bootstrap.
